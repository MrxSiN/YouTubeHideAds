# Known limitations and blockers (2026-10-15)

**Current, module iteration (2026-10-16):** version-code-21 is a real launcherless
module tested inside YouTube 21.41.525. It injects a Settings toolbar entry and
opens an in-process page with XAX callbacks. Navigation and a genuine BF engine
self-check passed on Vector 2.2. The module remains installed for YouTube only.

The page is currently a status page. No ad suppression, live SponsorBlock,
DexKit resolver or working feature preferences are present. The SettingsActivity
class/resource identity was verified only on the listed YouTube version; it is
not an all-version resolver. The artifact uses a local debug key. See
`history/ITERATION18_REPORT.md`; the missing-module/page claims below are historical.

**Latest, 2026-10-16:** the pinned XAX compiler has now built canonical stores,
JVM classes, native lifecycle exports and a real installable smoke APK. The new
managed XAX → BF call passed 4,463 comparisons on ART. Vector 2.2 loaded the
separate controlled lifecycle module and instantiated it once. Missing-tool,
missing-store, no-APK and no-device statements below are historical, superseded
by `history/ITERATION17_REPORT.md` and `evidence/xax_20261016/`.

The production gaps remain: no XAX validation of BFH1/BFR1 frames, Boolean
inputs, generations or action authorization; no DexKit bridge, verified YouTube
targets, hook actions, preferences, hot reload or live SponsorBlock. The raw
managed bridge is callable test infrastructure, not a trusted hook boundary.
Its tests use the existing JVM BF compiler; they do not connect BrainfuckC's
native ELF backend to an APK. XAX redistribution terms remain unresolved.

**2026-10-16 update:** Android SDK/NDK and ADB are available on the Windows
host. All twelve policies compiled with external BrainfuckC and passed 4,463
native/reference comparisons on a Pixel 8 Pro, Android 17 / API 37. The
historical missing-device statements below describe the previous environment.
The verified path is Android-shell callable ELF execution, with a bounded
compiler and different loop-gas accounting. It does not establish `dlopen`,
JNI, XAX host integration, an APK, Xposed hooks or YouTube ad removal. See
`docs/BRAINFUCKC_ANDROID.md` for the current evidence and backend limits.

1. No XAX canonical semantic store or Android host is generated by this repository yet. `xax_construct` at the pinned revision lists Linux, Windows, and JVM profiles for the general constructor; Android has different bounded build carriers. We cannot silently substitute a JSON request for canonical XAX source.
2. XAX compiler/store toolchain, Android SDK/NDK, D8, adb, Vector device and Android emulator are not installed or accessible in this execution environment. No APK, Xposed entrypoint, DexKit bridge, settings app or hot reload has been built.
3. XAX upstream has no root `LICENSE` found at the inspected revision; redistribute nothing from that repository until terms are resolved.
4. No installed YouTube DEX, device recordings or runtime objects are available. All `.bf` evidence flags are synthetic; production structural extraction and the corresponding Brainfuck feature algorithms remain to be designed and verified.
5. SponsorBlock has a real 64-bit segment-end output and six Boolean gates, but now has a separate Brainfuck-owned timestamp-window computation but still lacks its authenticated live player binding, overlap merging, video-ID lifecycle resolution, server parsing and verified playback seeking.
6. JVM AOT class compatibility with D8 and dynamic linkage into XAX DEX is untested.
7. No ad surface or YouTube version has yet been functionally tested, so compatibility matrix is empty.
8. No project-authored Java/Kotlin/XAX ad-filtering or host logic has been substituted as a shortcut.

## Iteration 2

The binary ABI is executed as **offline Python test tooling + real compiled JVM Brainfuck policies**, not the required XAX-authored Android runtime. It demonstrates framing/provenance/error behavior and intentionally cannot operate on live YouTube objects. The `authorize_seek` Brainfuck program now selects and emits a full 64-bit segment-end timestamp from input, but does not yet derive the segment-window predicate from raw timestamps; any positive seek action is still rejected at the reference boundary. No SponsorBlock playback action is available. `scripts/probe_android_integration.py` reports missing pinned XAX, Android SDK, D8, ADB, unresolved XAX redistribution rights, missing canonical XAX host and unrun Vector runtime checks.

Iteration 3: A project-authored adapter for the pinned XAX semantic Android API exists, but could not be executed against the absent compiler. Its external upstream test Activity is only a smoke test and does not satisfy the project's greenfield manager implementation. The offline APK/DEX verifier is deliberately bounded and can accept non-installable synthetic fixtures. No generated Android artifact, BF-to-DEX execution path, DexKit bridge, YouTube hook or SponsorBlock action is verified.

## Iteration 6 remaining limits

The SponsorBlock category selector now runs as real Brainfuck and its 2,048-case policy/JVM equivalence has been verified; it is not connected to Android. The host still lacks SponsorBlock HTTPS/JSON retrieval, per-video segment/generation lifetimes, authenticated live timeline data and XAX runtime wiring of the new Brainfuck temporal comparison, player hooks, and actual playback seek execution. The XAX toolchain, D8, Android SDK and ADB remain absent locally. Causal chain checking exists only as off-device conformance tooling.


**Iteration 13:** The one-call SponsorBlock policy eliminates the spoofable intermediate category Boolean but still takes host-derived generation/window/live-state flags. It neither fetches segments nor computes the full temporal policy from raw timestamps. The Java 65,535-byte method ceiling is addressed for this router by regional shared error handlers; arbitrary/unbounded Brainfuck programs may still exceed JVM method size or resource budgets. XAX Android runtime and hooks remain unverified.

**Iteration 14:** `sponsor_time_window.bf` determines 64-bit segment membership inside Brainfuck from 24-byte supplied timestamps. Its `06` authorization is transported through an off-device generation/endpoint-matching helper, not a trusted Android host. The actual timestamps can still be forged, stale, or unrelated to a video until classloader-safe, lifecycle-correct XAX hooks acquire them. The default 100,000-command budget is overridden to 2,000,000 only for the timestamp policy and the inline router. Java classfile method-size constraints remain a scaling blocker despite monotonic-pointer compaction.

**Iteration 15:** XAX source now directly composes the router JNI invocation
with the five-condition gate, deriving its exception-clear status from the
router's own `ExceptionCheck` result. Four separate integrity proofs remain
caller-supplied and untrusted; the native callback, runtime class provenance,
null handling, exception cleanup and verified reply-to-action transition are
not implemented. The opt-in five-function canonical graph store has not been
compiled or verified against external XAX, and Android execution remains absent.
