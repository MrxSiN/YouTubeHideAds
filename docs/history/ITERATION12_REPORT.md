# YouTubeHideAds — Iteration 12: exception-dependent XAX guard and reachable store

Date: 2026-10-15. **Research source, not a functioning Android module.**

## Implementation

1. `toolchain/xax/dispatch_guard.py` adds a fourth XAX semantic construction
   function using upstream `GraphBuilder`/`Operation.INT_COMPARE` and conditional
   branches. It accepts five *externally established* one-byte statuses:
   exception cleared, correct class name, exact defining loader, non-null
   method ID, and validated Brainfuck reply. Every byte must equal exactly 1
   to permit a host to consider the reply. This is **generic host integrity
   gating, not application feature logic**.
2. The source for the four graph functions is now included in the opt-in
   pinned-XAX canonical-store gate. The new XAX guard is **not wired** to the
   three existing JNI subroutines and has no Android export.
3. `root_reachable_closure()` collects only XAX semantic objects reachable
   through actual CIDs from the selected root; unavailable dependencies and
   conflicting objects fail closed. This removes misleading/unreachable
   construction helper objects from the canonical-store input.
4. Offline tests exhaust 4^5=1,024 status vectors, malformed input types,
   missing dependencies, missing root, and root conflicts. Updated docs and
   opt-in CI assert the structural nature of any verified XAX store.

## Explicit verification scope

- Python reference safety predicates and closure checks: executable offline.
- Previously implemented desktop JVM/JNI Brainfuck execution: tested again.
- XAX graph construction, type verification, canonical binary-store generation:
  **NOT RUN** locally; pinned external XAX compiler missing.
- Android DEX linking, libxposed/Vector, DexKit, real YouTube ad removal,
  SponsorBlock playback: **NOT RUN / NOT IMPLEMENTED**.
- The guard's five input statuses are not generated by an integrated XAX
  caller; a synthetic five-ones input does not authorize a device action.

## Subsequent acceptance gate

Build and verify the four graphs in the pinned external XAX compiler, then
connect loader acquisition, class-name/loader/code verification, method lookup,
current JNI exception branch, local-reference disposal, Brainfuck result-frame
validation and the guard into a single managed API-102 callback; validate on a
controlled Android device. No real suppression should occur until these checks
pass.
